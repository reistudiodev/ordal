# DB Client

A native, cross-platform database client (think DBeaver / Beekeeper Studio).

- **Rust core** (`core/`): all logic: connections, drivers, queries, schema browsing.
- **Swift bindings** (`swift/`): generated by [UniFFI](https://mozilla.github.io/uniffi-rs/), shared by every app.
- **Native UI per platform** (`apps/`): SwiftUI on macOS, WinUI on Windows, GTK on Linux.

```
.
├── Cargo.toml              Rust workspace
├── core/                   dbclient-core crate (the brain)
│   ├── src/lib.rs          public API exported to Swift
│   ├── src/drivers/        one module per engine, behind a Cargo feature
│   ├── tests/              integration tests (SQLite always; others need Docker)
│   └── uniffi.toml         Swift module names
├── uniffi-bindgen/         tiny CLI that generates the Swift bindings
├── swift/                  Swift package "DBClientCore"
│   ├── Sources/DBClientCoreFFI/   C header + module map (generated)
│   ├── Sources/DBClientCore/      Swift API (generated)
│   ├── Sources/DBClientKit/       shared view models for every platform (hand-written)
│   └── lib/                       Rust static lib goes here (build output)
├── apps/
│   ├── macos/              SwiftUI app
│   ├── windows/            placeholder (WinUI later)
│   └── linux/              placeholder (GTK later)
├── scripts/                build-core, package-macos, test-integration, seed-1m.sql
├── docker-compose.test.yml database servers for the integration tests
└── .vscode/                tasks, debug configs, recommended extensions
```

## Prerequisites

| | Rust | Swift |
|---|---|---|
| macOS | [rustup](https://rustup.rs) | `xcode-select --install` (Command Line Tools; full Xcode not needed) |
| Windows | rustup (MSVC toolchain) | [Swift for Windows](https://www.swift.org/install/windows/) + Visual Studio Build Tools |
| Linux | rustup | [Swift for Linux](https://www.swift.org/install/linux/) |

VS Code extensions are listed in `.vscode/extensions.json`; VS Code will offer to install them.

## Build and run

```sh
# 1. Build the Rust core, regenerate bindings, copy the static lib into swift/lib
./scripts/build-core.sh            # Windows: .\scripts\build-core.ps1

# 2. Run the app for your platform
cd apps/macos && swift run         # or apps/linux, apps\windows
```

In VS Code: **Terminal → Run Task → Run app**, or press F5 to debug.

Rust tests: `cargo test`. Swift tests: `cd swift && swift test` (after step 1).

## Do I need Xcode on the Mac?

No for day-to-day work. The Command Line Tools include the Swift compiler and the macOS SDK
(SwiftUI, AppKit), so everything builds and runs from VS Code. `scripts/package-macos.sh`
even makes a `.app` bundle without Xcode.

You'll want full Xcode only for: SwiftUI previews, asset catalogs / app icons,
App Store submission, or if you prefer Xcode's UI for signing.

## Adding to the core

1. Write Rust in `core/src/` and mark the API with `#[uniffi::export]`
   (functions, `impl` blocks) or derive `uniffi::Record` / `Enum` / `Object` / `Error`.
2. Run `scripts/build-core.sh`. The Swift side picks up the new API automatically.

Never edit `swift/Sources/DBClientCore/DBClientCore.swift` or the FFI header by hand: they are regenerated.
Hand-written Swift helpers go in new files next to them.

## Testing

```sh
cargo test                         # unit tests + SQLite; other engines are skipped
scripts/test-integration.sh        # Postgres 16, MySQL 8, MariaDB 10.11, MongoDB 7, Redis 7 in Docker
cd swift && swift test             # bindings + shared view models (after build-core)
```

Each server suite reads `DBCLIENT_TEST_<ENGINE>_URL` (`POSTGRES`, `MYSQL`, `MARIADB`, `MONGODB`, `REDIS`),
so you can also point it at servers you already run. The 1M-row scrolling gate:
load `scripts/seed-1m.sql`, then `cargo test --release --test postgres -- --ignored`.

## Development switches (macOS app)

- `DBCLIENT_HOME=/some/dir` keeps connections and history in that directory, with passwords in
  memory instead of the keychain. Use it to try the app without touching your real settings.
- `DBCLIENT_SNAPSHOTS=/some/dir` (with `DBCLIENT_HOME`) makes the app drive itself through the main
  screens against the first saved local Postgres connection, write PNGs and a `report.txt` with
  timings (connect, first page, scroll draw times), then quit. It renders offscreen, so sidebar and
  inspector materials appear blank in the images.

## Supported engines

| Engine | Driver | Query language |
|---|---|---|
| PostgreSQL | sqlx | SQL |
| MySQL 8 / MariaDB 10.6+ | sqlx | SQL |
| SQLite | sqlx | SQL |
| MongoDB | mongodb | JSON commands: `{"find": "users", "filter": {}}`, `{"aggregate": ...}`, any `runCommand` |
| Redis | redis | redis-cli commands: `HGETALL user:1` |

## Tables, editing and relations

- **Paging.** Table tabs show one page at a time (50–1000 rows). With a primary key (or `_id`,
  SQLite `rowid`, Postgres `ctid`) pages use keyset cursors, so the last page of a 100M-row table
  costs the same as the first. Views and MySQL tables without a key fall back to OFFSET, and the
  bar says so. Counts use the engine's estimate; **Count** runs an exact count with a 60 s limit.
- **Sorting.** Click a header: ascending, descending, off. Sorting runs on the server with NULLs
  last; sorting by a column no index starts with shows a warning because every page scans the table.
  Query results sort in memory once fully loaded.
- **Editing.** Select a cell in a table tab and edit it in the inspector (⌥⌘I). Input is checked
  against the column type (integer ranges, decimal scale, dates, UUID, JSON, enums, length, NULL).
  Changes are staged in yellow; **Review Changes** shows the exact SQL and applies everything in one
  transaction (MongoDB: one by one, keeping each field's BSON type). Rows need a primary key.
- **Relations.** Right-click a schema (Postgres) or database (MySQL, SQLite, MongoDB) → View Relations.
  SQL uses declared foreign keys; MongoDB relations are inferred from ObjectId fields named after a
  collection (`userId` → `users`) and drawn dashed.
- **Queries as files.** ⌘S / ⇧⌘S save the editor to a `.sql` file where you choose; ⌘O opens one.
